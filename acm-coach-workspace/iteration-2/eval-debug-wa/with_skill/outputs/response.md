## 诊断：问题不在类型，在算法

你说的类型问题确实存在（`ans` 是 `int`，`ans * a[i]` 可能溢出一会儿再谈），但**你 WA 的根本原因是算法完全错了**。这道题要求的不是求乘积。

---

## 第一步：重新读题

题目说：每次选**相邻两个数**，把**较小的删掉**。问最后剩下的数**最大可能是多少**。

关键洞察：**最大的那个数永远不会被删掉**。为什么？因为要删掉一个数，它必须是相邻 pair 中较小的那个。但数组的最大值不可能是任何 pair 中较小的那个——它大于等于所有数。所以最大值天然免疫删除。

因此答案就是 **`max(a)`**，即数组中的最大值。O(n) 扫一遍就行，根本不需要乘法、不需要模运算。

---

## 第二步：反例证明你的代码是错的

考虑这个极简单的输入：

```
1
3
2 3 1
```

- 你的代码输出：`2 * 3 * 1 % 1000000007 = 6`
- 正确答案：最大值是 `3`

操作演示：(2,3) 删 2 → [3,1]，再 (3,1) 删 1 → 剩下 3。输出应为 3，你的代码输出 6，WA。

## 第三步：你的代码里有哪些具体错误

逐行来看：

```cpp
int ans = 1;                                // 行5：即使算法对了，ans 也应该是 0 或 a[0]，不是 1
for (int i = 0; i < n; i++) {
    ans = ans * a[i] % 1000000007;          // 行7：① 算法错——这算的是乘积模 10^9+7

                                            //       超出 int（2×10^9），在取模前就溢出了
}
```

你猜"ans 的类型可能有问题"猜对了方向——如果你非要用这个算法，应该用 `long long ans = 1`，或者 `ans = 1LL * ans * a[i] % MOD`。但这些都是次要的，因为**算法本身就不对**。

## 第四步：正确写法

```cpp
#include <bits/stdc++.h>
using namespace std;

void solve() {
    int n; cin >> n;
    vector<int> a(n);
    for (int i = 0; i < n; i++) cin >> a[i];
    int ans = *max_element(a.begin(), a.end());  // 就这一行
    cout << ans << '\n';
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    int t; cin >> t; while (t--) solve();
}
```

复杂度 O(n)，在 n ≤ 2×10^5 下绰绰有余。

## 总结

| 问题 | 严重程度 | 说明 |
|------|---------|------|
| 算法错误（乘法 vs 最大值） | **致命** | 整个逻辑不匹配题意 |
| 模运算不必要 | 高 | 题目没要求取模 |
| `int` 溢出 | 中 | `ans*a[i]` 在取模前溢出（如果你偏要用乘法的话） |
| `ans` 初始化 =1 | 低 | 对正确算法（max）不相关 |

核心教训：**最大元素永远不会被删，因为它不可能是任何相邻 pair 中较小的那个**。很多操作类的题目都有这种"某个特殊元素天然免疫"的性质，抓住了就能把复杂问题化简为一行。
