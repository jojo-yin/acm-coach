## 题目分析 -- 教练模式

你好！这题完全没思路很正常，因为它的贪心策略不是一眼能看出来的。我们按照四步分析法，一步步来推。

---

### Stage 1: 读约束，定复杂度

```
n ≤ 2×10^5
l_i, r_i ≤ 10^9
```

根据复杂度对照表，**n = 2×10^5 意味着你的算法必须是 O(n log n) 或更快**。O(n^2) 肯定超时。

所以你能做的操作是：**扫描几遍数组 + 排序**。这就排除了暴力的区间两两比较。

---

### Stage 2: 设计算法

我们先来理解问题本质：你要用最少的点，「覆盖」所有区间。换句话说，**你希望每个点落在尽可能多的区间里**。

**引导性问题：** 如果一个区间比其他区间更早结束，你会优先考虑它的什么位置来放点？

想想看... 如果一个区间在 r 位置结束，而你选的点的坐标 > r，那这个区间就没被覆盖。所以**为了覆盖这个区间，你至少要在 ≤ r 的位置放一个点**。那放哪里最好？当然是放在 r 本身——这个位置既覆盖了当前区间，又最靠右，最有可能同时覆盖后面的区间。

这就引出了关键思路——

**直觉：** 你害怕漏掉那个最早结束的区间。所以应该优先处理它，在它的右端点放一个点，然后所有包含这个点的区间就都被覆盖了，可以跳过。接着找下一个还没被覆盖的区间，重复。

**具体步骤（贪心策略）：**

1. **按右端点 r_i 升序排序**所有区间
2. 初始化 `last_point = -∞`（上次放点的位置），`count = 0`
3. 遍历排序后的区间 `[l, r]`：
   - 如果 `last_point < l`：说明当前区间没被覆盖，在 r 处放一个新点，`count++`，更新 `last_point = r`
   - 否则：当前区间已经被 `last_point` 覆盖，跳过
4. 输出 `count`

**复杂度：** 排序 O(n log n)，一次遍历 O(n)。总共 **O(n log n)**，符合约束！

---

### 为什么这个贪心是正确的？

这是最核心的问题——很多贪心「看起来对」但其实是错的。我们快速验证一下：

**交换论证：** 假设最优解在某一步没有选右端点，而是选了更靠左的点。如果把这个点向右平移到右端点，它覆盖的区间一定不会变少（因为右端点仍然是区间内的点，而且更靠右，能覆盖更多以更右边为左端点的区间）。所以选择右端点不会比最优解差。

你也可以这样想：**按右端点排序后，第一个区间的右端点是你必须覆盖的「最早 deadline」——你必须在 ≤ r1 的某处放一个点，而放在 r1 给了后面区间最大的被覆盖机会。**

---

### Stage 3 & 4: 代码骨架和验证

到了这里，你可以自己写代码了。骨架是这样的：

```cpp
// 1. 读入 n 个区间
// 2. 按 r 升序排序
// 3. 遍历，维护 last_point 和 count
// 4. 输出 count
```

**动手之前，先用手跑一下例子：**

假设区间：`[1,3]`, `[2,5]`, `[4,6]`

- 按 r 排序后：`[1,3]`, `[2,5]`, `[4,6]`（已经是右端点升序）
- 处理 `[1,3]`：last_point 初始 < 1，在 r=3 放点，count=1
- 处理 `[2,5]`：last_point=3，3 ≥ 2，已覆盖，跳过
- 处理 `[4,6]`：last_point=3，3 < 4，在 r=6 放点，count=2
- 答案：2 个点（位置 3 和 6）

手动验证：点 3 覆盖前两个区间，点 6 覆盖第三个。确实 2 个点就够了，也是最少的。

---

### 一个小陷阱

排序时注意：如果两个区间的**右端点相同**，按什么顺序排？要不要特殊处理？

想一下：如果 `[1,5]` 和 `[3,5]` 右端点都是 5，谁先谁后有影响吗？

（提示：没有影响——因为在 5 放一个点，两个区间都被覆盖了。但为了便于理解，你可以按左端点升序作为第二关键字，这不是必须的。）
