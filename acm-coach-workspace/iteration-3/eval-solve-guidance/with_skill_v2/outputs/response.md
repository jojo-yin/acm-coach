好，这道题经典又漂亮，我们按四个阶段来过一遍。

---

## Stage 1: READ — 约束分析

先看数据范围：
- n ≤ 2 × 10^5
- l_i, r_i ≤ 10^9

这意味着什么？对照复杂度表：
- 允许 O(n log n) 或 O(n)
- **O(n²) 绝对会 TLE**

所以我们在设计算法时，必须把复杂度控制在 O(n log n) 以内。

---

## Stage 2: THINK — 算法设计

好，现在我来问你第一个引导问题（你先想想，然后我接着讲）：

> 假设你已经选好了一些点。对于**某一个**区间来说，你觉得这个区间最"希望"你选的点在什么位置？换句话说，如果一个区间一定要被覆盖，你选它的哪个位置最"划算"？

---

想好了吗？关键思路在这里：

**每个区间，你只需要选一个点。选在右端点最划算。**

为什么？我们做个交换论证：

1. 假设最优解中，区间 [l, r] 被覆盖的点是 p，且 p < r（不是右端点）。
2. 把 p 向右移到 r，会发生什么？
   - 选 r 仍然覆盖了本区间（因为 r 在区间内）。
   - 所有原本被 p 覆盖的区间，右端点 ≥ p，**但未必 ≥ r**——等等，这里有问题。

让我重新来过。正确的贪心策略是：

### 算法：按右端点排序的区间选点

**做法：**
1. 将所有区间按**右端点**从小到大排序。
2. 维护一个变量 `last` 表示上一个选的点。
3. 遍历每个区间 [l, r]：
   - 如果 `l > last`（当前区间没有被已选的点覆盖），则在它的右端点 `r` 处放一个新点，令 `last = r`，答案 +1。
   - 否则，跳过（已被覆盖）。

---

### 为什么按右端点排序 + 选右端点是最优的？（交换论证）

假设按右端点排序后，贪心算法选的点集为 G = {g₁, g₂, ...}，最优解的点集为 OPT = {o₁, o₂, ...}（均按坐标递增排列）。

我们证明 |G| ≤ |OPT|。

**归纳比较：** 按排序后的区间顺序比较贪心解和最优解覆盖到的第一个"未被覆盖"的区间。

- 设贪心选的第 k 个点 g_k，位于某个区间 I_k 的右端点。
- OPT 中覆盖 I_k 的点是 o_k（即按顺序覆盖 I_k 的那个点），一定有 o_k ≤ g_k。
  - 为什么？因为 I_k 的右端点是所有未被覆盖区间中右端点最小的，OPT 要覆盖 I_k，选的点的位置 ≤ g_k（否则说明 OPT 没覆盖到 I_k，矛盾）。
- 但 o_k 覆盖了 I_k 之后，最多能把覆盖延伸到 o_k 的右边界。而 g_k = I_k 的右端点 ≥ o_k，所以 G 用 g_k 覆盖的范围不短于 OPT 用 o_k 覆盖的范围。
- 因此 G 的覆盖进度 ≥ OPT 的覆盖进度。归纳下去，G 不会比 OPT 多用更多的点。

所以贪心最优。

---

**复杂度：** 排序 O(n log n)，遍历 O(n)。完美满足 n ≤ 2×10^5 的约束。

**边界情况：**
- n = 1：直接选右端点，答案 1。
- 所有区间相互分离（[1,2], [3,4], [5,6]）：每个区间都需要一个点。
- 所有区间重叠覆盖同一个点：只需要 1 个点。

---

## Stage 3: CODE — 结构

既然你说了不要完整代码，我给你伪代码：

```
输入 n
读入所有区间 (l, r)
按 r 排序
last = -INF  (或者 -1e18)
ans = 0
for 每个区间 (l, r):
    if l > last:
        ans += 1
        last = r
输出 ans
```

核心代码就 7-8 行。几个编码注意点：
- `last` 初始化为一个足够小的负数（比如 -1e18 或 `-2e9-5`），因为 l, r 可以到 10^9。
- 排序用 `sort` + lambda 按右端点排。
- `long long` 不是必须的（10^9 不超 int），但习惯用 `long long` 更安全。

## Stage 4: VERIFY

手动跑样例验证。你没有给具体样例，但我建议你用这个样例检验：

```
输入：
3
[1, 3]
[2, 5]
[4, 6]

排序后：[1,3], [2,5], [4,6]
第1个区间：1 > -INF → ans=1, last=3
第2个区间：2 ≤ 3 → 跳过
第3个区间：4 > 3 → ans=2, last=6
输出：2
```

验证：选 3 和 6 两个点，三个区间都覆盖到了。最优解也是 2，正确。
