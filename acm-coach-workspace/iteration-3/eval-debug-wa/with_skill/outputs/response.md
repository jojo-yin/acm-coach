## Path B — 调试诊断

### 问题定位

代码的**算法完全不对**，不是类型问题。

一段段来看：

**问题理解**  
每次操作选相邻两个数，删掉较小的，较大的留下。重复操作直到只剩一个数。问最后剩下的数最大可能是多少。

**关键观察**：全局最大值是整个数组中最大的数，没有任何数比它更大，所以它**永远不会被删掉**（跟谁相邻它都是较大的那个）。同时，你总是可以通过操作把其他所有数逐步删光。因此 **答案就是数组的最大值**。

**你的代码在做什么：**

```cpp
int ans = 1;
for (int i = 0; i < n; i++) {
    ans = ans * a[i] % 1000000007;
}
```

这段代码在求**所有元素的乘积 modulo 1000000007**，跟题目想问的完全是两回事。样例能过只是巧合（比如样例恰好是单个元素，或乘积取模后等于最大值）。

**次要问题**（即使题目是求乘积）：`ans` 是 `int`，`ans * a[i]` 在取模之前就已经溢出（两个 ≤ 10^9 的 int 相乘 ≈ 10^18，超出 int 范围）。但这不是主因。

### 修复建议

把计算乘积的循环替换成求最大值：

```cpp
int ans = *max_element(a.begin(), a.end());
```

或者手动：

```cpp
int ans = a[0];
for (int i = 1; i < n; i++) {
    if (a[i] > ans) ans = a[i];
}
```

注意答案本身就是数组中的元素，值 ≤ 10^9，`int` 完全够用，不需要取模。

### 验证思路

构造一个反例：

```
a = [5, 1, 100, 2]
```

你的代码输出：`5 * 1 * 100 * 2 % MOD = 1000 % MOD = 1000`  
正确答案：`max = 100`  

说明：先删 5 和 1 中的 1（剩 `[5, 100, 2]`），再删 100 和 2 中的 2（剩 `[5, 100]`），最后删 5 和 100 中的 5，剩下 100。

---

**总结**：题目的操作特性保证了最大值一定存活，这是经典的结论。理解这个性质比修类型问题更重要。
